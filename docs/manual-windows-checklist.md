# Ручная проверка Windows 11

Статус: выполнять на демонстрационном компьютере. Автотесты не подтверждают эти пункты.

1. Записать оборудование и версии зависимостей. Выполнить профиль камеры на 60 с,
   затем повторить с обычной фоновой нагрузкой. Сохранить JSON. Выбрать таймауты
   с учётом допустимого интервала отсутствия контроля, а не только средней задержки.
2. Запустить без `--lock-keys`: до первого свежего анализа PAUSED, затем RUNNING.
   Проверить изображение, возраст кадра и журнал.
3. Выбрать ответ. Отключить камеру: PAUSED, ввод/отправка недоступны. Подключить
   обратно: продолжение после нового анализа, ответ сохранён.
4. Переключиться мышью в другое окно: PAUSED и `violation/focus_lost`. Вернуться:
   восстановление после свежего анализа. Принудительная активация не ожидается.
5. Одновременно потерять фокус и отключить камеру. Вернуть только фокус: всё ещё
   PAUSED. Вернуть камеру: продолжение после нового анализа.
6. Показать телефон, убрать, показать снова: два эпизода phone. Проверить отсутствие
   лица и второе лицо при разном освещении и расстоянии; записать ложные срабатывания.
7. Проверить длительный отвод взгляда, повороты головы, сброс длительности при
   возврате и разрыве анализа. Это эвристики, не объективное доказательство списывания.
8. Перезапустить с `--lock-keys`. Проверить сочетания в целевом окне и обычный ввод
   вне него, удержание клавиши при смене фокуса, Ctrl+Shift+F12. После выхода хуки сняты.
9. Проверить `frame_age_ms`, `analysis_gap_ms`, `ui_tick_gap_ms`, RAM процесса.
   Холодный старт и устойчивую работу оценивать отдельно.
10. Закрыть и открыть с тем же `--data-dir`: ответы сохранены, старт PAUSED.
    Отправить, открыть снова: STOPPED. Проверить report.json и metrics.json.

Зависание можно продемонстрировать переключателем `--demo`; это не замер реального
нативного зависания. Автотесты отдельно задерживают обработчик через threading.Event.
Используйте отдельные каталоги для симуляции и реальных замеров.
